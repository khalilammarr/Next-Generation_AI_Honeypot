# 🕸️ GhostNet: Professional Cyber-Intelligence Engine
**Master Architectural Specification v3.5 (Post-Deployment Edition)**

This document details the exact mechanics of the **Behavioral Analysis Platform**, focusing on the technical integration between the raw capture layer, the persistent database, and the on-demand AI reasoning core.

---

## 🏛️ 1. Database Infrastructure (The Persistence Layer)
GhostNet utilizes a **relational storage model** built on **SQLite 3**. This choice ensures sub-millisecond local query performance while maintaining single-file portability.

### 🏛️ Table Model: `sessions` (Session Metadata)
This table stores the state of each unique attacker "Campaign". We use a specialized indexing strategy to ensure fast lookups by IP.

| Field | SQL Type | Description |
| :--- | :--- | :--- |
| **`id`** | `INTEGER` | Auto-incrementing internal primary key. |
| **`session_id`** | `TEXT` | **Unified Unique Identifier**. For Cowrie (SSH), it is the UUID provided by the protocol. For HTTP, it is a SHA-256 hash of `IP + UserAgent + TimeWindow`. |
| **`ip_address`** | `TEXT` | Attacker's source IP (IPv4/IPv6). Index: `idx_sessions_ip`. |
| **`protocol`** | `TEXT` | One of `['SSH', 'HTTP']`. |
| **`start_time`** | `TIMESTAMP` | ISO-8601 formatted string of the first interaction. |
| **`end_time`** | `TIMESTAMP` | Updated on every new event to compute session duration. |
| **`risk_level`** | `TEXT` | Initial: `UNKNOWN`. Updated by `llm_analysis.py` to `['LOW', 'MEDIUM', 'HIGH', 'CRITICAL']`. |
| **`analysis_summary`** | `TEXT` | Long-form semantic reasoning generated by the LLM. |
| **`mitre_mapping`** | `TEXT` | **Serialized JSON Array** containing mapped MITRE ATT&CK codes (e.g., `["T1059.004", "T1071.001"]`). |

## 🔁 2. The Analysis Reasoning Cycle (Step-by-Step)
Instead of continuous analysis (which is costly and noisy), GhostNet uses an **On-Demand Forensic Model**.

### Step A: The Reconstruction (DB Read)
When the user clicks `Analyze_Tactics` in the dashboard:
1.  **Backend Fetch**: `app.py` queries the `events` table: `SELECT * FROM events WHERE session_id = ? ORDER BY timestamp ASC`.
2.  **Context Construction**: The individual interaction lines are concatenated into a **Threaded Discourse Fragment**.

### Step B: The AI Cognitive Processing
The thread is passed to the **Intelligence Probe** (`llm_analysis.py`).
1.  **System Prompt Enrichment**: We inject a "Senior CTI Analyst" persona with specialized knowledge of Linux internals and HTTP exploitation.
2.  **Reasoning Pipeline**: The LLM (Kimi-k2) performs:
    *   *Semantic De-obfuscation*: Identifying what complex shell commands (like `base64 -d`) actually do.
    *   *Intent Extraction*: Is this a scripted bot looking for crypto-miners or a human looking for SSH keys?
    *   *Risk Scoring*: Calculating risk based on the severity of the commands (destructive commands = `CRITICAL`).

### Step C: The Persistence Writeback (DB Update)
Once the LLM returns the JSON structured report:
1.  **Atomicity**: The `sessions` entry is updated in a single transaction.
2.  **Normalization**: The `mitre_mapping` JSON string is parsed to ensure schema validity before being stored.

## 🛡️ 3. Symbiote Relationship with Wazuh
*   **Wazuh's Role**: Real-time **Signature-based** detection. It reacts when an IP matches a known blacklist or a single file is modified.
*   **GhostNet's Role**: Post-attack **Heuristic** intelligence. It uses the database to bridge the gap between "something happened" and "here is why it happened."

### 🔬 User Case Example:
An attacker performs a slow, 2-hour reconnaissance. Wazuh might miss the pattern as individual actions seem "Low Risk". 
1.  **Database Storage**: Every single silent `ls` and `cd` is recorded in SQLite.
2.  **AI Analysis**: When you click Analyze, the LLM reads the **full 2-hour timeline** once, recognizes the pattern of a sophisticated manual exploration, and upgrades the Risk Index to **HIGH**. 🛡️📊🚀
